# Legacy Code Audit

## Critical findings

### A1. Synthetic anomaly rates are incorrect

The legacy anomaly script selects `int(n * rate)` event starts, but a level-shift event labels up to three timestamps. The actual positive-label rate therefore exceeds the nominal 5% or 10% rate.

### A2. Injected values are not used by downstream models

The legacy anomaly script writes anomalies to `y_anom`, while downstream forecasting scripts read precomputed clean `X_test`/`y_test` or `test["y"]`. The anomaly predictions are therefore computed on the clean test series and then compared with injected labels. This invalidates synthetic anomaly Precision, Recall, and F1.

### A3. Isolation Forest is incorrectly treated as a forecasting model

The baseline script creates heuristic one-step values around Isolation Forest flags and records them as `scenario=forecast_original`. The final table builder then ranks Isolation Forest together with ARIMA, XGBoost, LSTM, and NFGA. This caused the invalid Cholera ranking challenged by the reviewers.

### A4. The file named `su07_prophet.py` is not Prophet

The recovered file implements a gated NFGA–ARIMA hybrid and writes to `gated_nfga_arima_results`. A genuine Prophet implementation is currently missing from the recovered set.

### A5. The stated walk-forward protocol is not implemented consistently

ARIMA is refitted step-by-step. XGBoost, LSTM, and NFGA use static precomputed test windows and do not update their history or retrain at every test timestamp. The manuscript must either describe the actual fixed-model recursive/direct protocol or the code must be changed to a common walk-forward protocol.

### A6. NFGA model parameters are optimized against validation data

The legacy GA fitness is evaluated on the held-out validation block. Since chromosome values are model parameters, not merely hyperparameters, this effectively trains on validation data. The corrected implementation must optimize on the fit partition and use validation only for selection/early stopping.

### A7. NFGA local linear consequents do not match the manuscript equations exactly

The legacy consequents use five engineered features: last value, window mean, slope, window standard deviation, and bias. The manuscript describes coefficients over each of the `w` lagged inputs. The code and methodology must be reconciled explicitly.

### A8. Timing is reported incorrectly

Several scripts report training time divided by the number of test points as `avg_time_sec`. This is neither training time nor inference latency. Corrected outputs will report total training time, total inference time, latency per sample, and peak memory separately.

### A9. Final table generation accepts heterogeneous and invalid rows

The legacy table builder includes every `forecast_original` row, including Isolation Forest. It also computes a global mean RMSE across datasets with incompatible measurement scales. The global raw-scale summary must be removed or replaced by scale-free ranks/normalized metrics.

### A10. Figure generation has implementation defects

The Wilcoxon figure builds colors from the unsorted table while plotting the sorted table, and it closes the figure without saving it. Ablation bars on a raw linear scale hide ILINet and Electricity behind Cholera's scale.

## Decision

The legacy scripts are frozen for provenance only. The revised paper will use only outputs generated by the corrected pipeline and validated by automated checks.
